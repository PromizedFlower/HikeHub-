## 一、運行 Demo

### 1. 環境準備（全新機器）

```powershell
cd <專案根目錄>\hikehub\hikehub
pip install -r requirements.txt
```

`.env` 已隨專案提供（模板為 `.env.example`），內容見第三節。若缺失，請將 `.env.example` 複製為 `.env` 並填入第三節的 URL 與 anon key。

### 2. 啟動

```powershell
python main.py
```

- 視口：390 × 844（iPhone 14 邏輯解析度），底部 5 個 Tab（首頁 / 線路 / 出發 / 社區 / 我的）。
- 登入頁頂部應顯示 **`✓ Supabase 環境已就緒：Supabase Cloud (已連線)`**。
  若顯示「本地鏡像同步模式」或「未配置 .env」，代表未連上雲端，請檢查 `.env`。

### 3. 建議演示動線

| 步驟 | 頁面 | 可展示內容 |
|---|---|---|
| 1 | 登入頁 | 「一鍵填入」6 個預建帳號；輸入錯誤密碼會明確提示「密碼錯誤，預建測試帳號密碼統一為 HikeHub2026!」 |
| 2 | 首頁 / 線路 | 10 條香港真實行山路線；區域、難度篩選；路線詳情含路段、補給點、撤退點 |
| 3 | 出發 | QtLocation OSM 地圖、路線軌跡折線、雙源定位（演示模式座標 `22.228367, 114.242633`）、打卡點 |
| 4 | 社區 | 動態 / 問答 / 行山記錄三類貼文；點讚、評論、收藏、問答「採納」 |
| 5 | 我的 | 編輯暱稱、個人簡介、頭像 |
| 6 | 持久化驗證 | 於 App 內點讚或發文後，換帳號登入或關閉重開，資料仍在（真實寫入雲端 Postgres） |

### 4. 交付 Windows 執行檔（本機已完成）

本機已產出 **`dist/HikeHub.exe`**（約 193 MB，PyInstaller 6.22.3 onefile、`console=False`）。
在未安裝 Python 的 Windows 機器上**直接雙擊即可啟動**，無需複製 `.env`：

- `.env` / `.env.example` 已打包進 exe；啟動時依「exe 同目錄 `.env` → `_MEIPASS/.env` →
  exe 同目錄 `.env.example` → `_MEIPASS/.env.example`」回退鏈讀取。
- QtLocation OSM 外掛（`qtgeoservices_osm.dll`）、QtQuick / QtLocation / QtPositioning QML 模組、
  `qwindows.dll` 一併打包，五個 Tab 與地圖皆可用。
- 首次啟動於背景同步雲端 9 張表（不阻塞介面），完成後自動刷新各頁；登入時會再補一次同步。

重新打包：

```powershell
python -m PyInstaller build.spec --noconfirm
```

**交付邊界**：產物只保留本機 `dist/HikeHub.exe`，不複製到桌面、不推送 GitHub。
`.env` 僅含公開 anon key，安全性由 RLS 保護。

**離線行為**：雲端不可達時，登入頁顯示「⚠️ 離線演示模式」並說明資料僅存本機；
寫操作降級為本機鏡像且提示帶「離線演示，資料僅存本機」，重新連線後以雲端為準。
錯誤密碼在任何模式下都無法登入。

> **雲端 SQL 補強（v5.1）**：本機已更新 `schema.sql` / `policies.sql` /
> `all_in_one.sql` / `verify_db.sql` / `EXECUTE.md`，但本機無 Management API 憑據，
> 需由你在 Supabase SQL Editor 貼上 `supabase/all_in_one.sql` 執行一次（可安全重跑）。
> App 核心寫入不依賴這一步；補強是防長期資料漂移與越權寫入的防線。

### 3. 建庫與驗證檔案

依序執行（詳見 `supabase/EXECUTE.md`）：

1. `supabase/create_auth_users.ps1` — 透過 **Auth Admin API** 建立 6 個可登入帳號
2. `supabase/schema.sql` — 9 張表、索引、外鍵、計數 Trigger
3. `supabase/policies.sql` — RLS 政策與 Storage bucket
4. `supabase/seed.sql` — 真實香港行山種子資料
5. `tests/verify_db.sql` — 表行數、計數一致性、RLS、外鍵驗證

> **重要技術備註**：新版 Supabase 的 GoTrue 不認可用 SQL 直接 `INSERT INTO auth.users` 建立的帳號（即便補齊 `instance_id`、`auth.identities`、bcrypt，登入仍回 `invalid_credentials`）。帳號必須透過 Auth Admin API 建立。此外新版 `auth.identities` 新增 NOT NULL 的 `provider_id` 欄位。

## 五、安全須知

1. **anon key** 設計為前端公開使用，安全性由 RLS 保護，可隨專案提交。
2. **Access Token（`sbp_...`）**、**service_role key**、**Direct connection string（含資料庫密碼）** 權限極高，**絕不可寫入 repo、`.env` 或本留檔**；用完請至 Supabase 後台 Revoke。
3. 本檔僅保留可公開的 URL 與 anon key。
4. PowerShell 控制台中暱稱可能顯示為亂碼（終端編碼問題），**QML 介面顯示正常**，不影響功能。
