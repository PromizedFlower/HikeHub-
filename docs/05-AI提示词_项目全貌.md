## 0. 一句话简介

「行山腳 HikeHub」是一款面向香港山友的桌面社群应用：以结构化的 10 条香港行山路线
为基础，让用户浏览路线、模拟/真实定位出发打卡，并把沿途照片与心得发布到社区，进行
点赞、评论、收藏与问答采纳互动。数据真实落在 Supabase 云端，离线时明确降级演示。

## 1. 项目背景与目标

- **课程背景**：COMP 7510 团队项目，4 人协作（Member A/B/C/D，详见 `docs/团队分工表.docx`）。
- **产品定位**：极简行山社交，不做商城/私信/推荐算法，聚焦「找路线 → 出发打卡 → 分享互动」。
- **目标**：可演示、可打包交付（`dist/HikeHub.exe`）、数据真实可追溯、界面港式繁体。
- **交付形态**：390×844 手机视口桌面程序，开发用 `python main.py`，交付用双击 `HikeHub.exe`。

## 2. 技术栈

| 层 | 技术 |
|---|---|
| 界面 | PySide6 (Qt 6) + Qt Quick / QML + QtLocation（OSM 地图）+ QtPositioning |
| 桥接/服务 | Python 3.11+（本机实测 3.13）`bridge.py`（Slot/Signal）→ `*_service.py` |
| 数据 | Supabase Postgres 9 表 + Auth + Storage（`trail-photos` bucket）；supabase-py |
| 打包 | PyInstaller onefile（`build.spec`），`console=False`，含 `.env` 与 OSM 插件 |

## 3. 需求说明（功能清单）

**5 个底部 Tab**：首頁 / 線路 / 出發（凸起） / 社區 / 我的。

- **首頁**：本周精选路线、行程统计、快捷入口。
- **線路**：10 条香港路线列表，按地区/难度/时长/关键词筛选，详情含分段（补给点/撤退点）与打卡点。
- **出發**：选路线 → 开始行程 → 系统/模拟双源定位 → 轨迹推进 → 打卡/加相片 → 结束结算。
- **社區**：动态流（moment/trip 卡片）、行山问答（question）、发帖、点赞、评论、收藏、采纳回答。
- **我的**：个人资料、行山次数/动态数/收藏数、我的动态（可快速修订）、我的收藏（路线/动态）。

**本轮新增（社区分享简化）**：
- 发布页从「固定候选图 + 手填路径」改为 **本地多图选择（FileDialog）→ 发布时上传云端 Storage**。
- 不再使用小红书/户外 App 数据；示例图全部改用 **Unsplash 开源图**（学生作业，无需考虑版权）。
- 移除内容管理与审核（项目本就没有审核代码，仅确认不引入）。

```

├── app/
│   ├── main.qml                 # 5 Tab 主壳
│   ├── theme/ components/       # 设计规范与 13 个共用组件
│   ├── pages/                   # SignIn/Start/RouteList/RouteDetail/Community/PostDetail/Compose/Profile/EditProfile...
│   └── backend/
│       ├── bridge.py            # L2：@Slot/@Property/Signal，QML ↔ service 的唯一桥梁
│       ├── remote_store.py      # [新增] L3.5：远端优先写入/回读/镜像同步/离线降级
│       ├── supabase_client.py   # 连接、.env 回退链、会话、本地镜像、DEFAULT_SEED_DATA

│       ├── post_service.py      # 发帖/编辑/删除、图片上传、post_photos
│       ├── social_service.py    # 点赞/收藏/评论/采纳
│       ├── trail_service.py     # 路线列表/详情/筛选
│       ├── location_service.py  # 双源定位
│       └── workers.py           # 后台线程池
├── supabase/                    # schema/policies/seed/all_in_one.sql、EXECUTE.md
├── tests/                       # test_01~06 验针 + verify_db.sql
├── assets/route-photos/         # [新增] 10 路线 × 3 张开源素材图（演示上传用）
└── docs/                        # 留档、测试教程、分工表、素材包、本提示词、工作日志
```

**四层单向依赖**：QML → `bridge.py` → `*_service.py` → `remote_store.py` → Supabase。

## 6. 关键协作约定（红线）

1. **四层单向依赖**：QML 不写业务/不碰数据；数据访问收敛在 service 层。
2. **契约冻结**：`bridge` 的 Slot/Property 名称、5 Tab 索引、固定 UUID、seed 数据行不改；
   新增能力用「加模块」（如 `remote_store.py`）而非改接口。
3. **单一数据源**：在线以云端为准并刷新镜像；离线只用镜像且显式标注，绝不「提示成功但数据未变」。
4. **失败语义**：写操作返回结构化结果（`ok/data/offline/error`），`bridge` 仅在 `ok=True` 时提示成功。
5. **安全**：仅公开 anon key 可入库；Access Token / service_role / DB 直连串绝不入 repo 或日志。
6. **界面**：港式繁体、沿用 `Theme.qml` 配色与字级；不改动现有固定 UUID 数据。
